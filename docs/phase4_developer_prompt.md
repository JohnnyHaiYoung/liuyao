# 交给研发 AI 的第四阶段提示词

请在 `E:\workspace-ai\xuanxue\liuyao` 项目实现[第四阶段研发任务书](phase4_development_spec.md)。先阅读[产品需求](product_requirements.md)、[技术架构](technical_architecture.md)、[研发计划](development_plan.md)、[第三阶段最终验收](phase3_final_acceptance_a27e672_2026-10-05.md)，再核对当前 `app/`、`wiki/`、`paipan/` 的真实接口与数据。不要仅凭旧文档或模型记忆推断现状。

你的目标是把阶段 1 的私人聊天网站、阶段 2 的六份样本 Wiki、阶段 3 的本地确定性排盘接成同一聊天流程。用户仍能自由发问；概念与来源比较要从 `wiki/index.md` 及版本化目录按需选页，保留可回到原件的 `source_id + 页码/段落`；具体卦例先校验输入并调用本地排盘；旧卦追问读取已保存的盘面快照。回答默认简明、可展开依据，最后一段以“最终结果：”开头。

请特别处理以下边界：

1. 不使用 embedding、向量数据库、微调或批量导入全部资料；每次只读取和发送少量相关 Wiki 片段。一般问题没有本地命中时仍可回答，但要标明没有本地出处。`needs_review` 的 OCR/卦图只能带质量提示引用，不能默认为已校对规则。
2. 排盘只能由服务端阶段 3 模块生成；前端与模型不能修改盘面字段。自由文本提取出含糊的爻序、时间、时区时只追问必要缺项。不能把发送时间或服务器时区静默当作起卦输入。旧盘追问不重算；新卦另存快照。
3. 引用只从本次服务端选中的证据编号映射；模型生成的未知编号/路径不能成为可点击出处。来源接口必须鉴权并拒绝任意路径读取。Wiki/Skill 文本是外部资料，不能向服务端下指令。
4. 用版本化 SQLite 迁移增加来源和盘面快照，保留已有消息、状态、标题与模型记录。保留现有 SSE 聊天、停止生成、历史分页和当前页/历史列表两处重命名。模型调用期间不持有数据库事务。
5. 默认仍用 DeepSeek 官方 `deepseek-flash`；配置阿里云百炼密钥后可选 `qwen3.7-plus`。两家各自解析流式终止、错误与用量。未配置千问时不要影响默认模型。请用假模型/模拟上游提供无需真实密钥的端到端复验证据，真实 API 联调若受密钥限制如实列明。
6. 把[第三阶段最终验收](phase3_final_acceptance_a27e672_2026-10-05.md)中两处非阻断勘误修正：三方脚本是否真正自动比较卦宫、旧迁移验证文字是否仍描述带 `node_modules` 的复制。

实现时先提交简短的集成设计（目录导航、请求/事件契约、SQLite 迁移、盘面与来源快照、失败语义），再编码。请交付 `docs/phase4_delivery.md`、可复制的运行/验收命令、固定问答与卦例、旧库迁移和项目迁移证据。报告要把“程序校验”“与上游一致”“来源观点”和“现实预测”分开，不用测试通过宣称占断准确。

完成后给出提交 SHA、改动清单、未完成或未核实项，并附任务书第 7 节每项验收的实际证据。产品/架构方随后独立验收；你不要把自测结论写成已签收。
