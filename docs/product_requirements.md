# 六爻 Agent 产品需求（交付开发用）

版本：2026-10-01。产品为**个人使用、部署在服务器上的网页应用**。本文规定用户可见的行为；技术实现见 [技术架构](technical_architecture.md)，顺序见 [研发计划](development_plan.md)，验收项见 [验收清单](acceptance_checklist.md)。

## 1. 产品目标

用户可以像普通 AI 聊天网站一样自由提问，继续已有对话，并查看历史。Agent 结合项目内的六爻 Wiki、必要时调用确定性排盘工具，对概念、资料差异和具体卦例作答。回答默认简明，用户要求时展开依据，最后给出「最终结果」。

资料尚未全部清洗，产品须明确当前知识覆盖范围。传统占断属于来源中的解释，不应包装成已验证的现实预测。

## 2. 第一版功能

| 优先级 | 功能 | 用户可见的行为 |
| --- | --- | --- |
| P0 | 自由聊天 | 输入任意问题并发送；页面逐步显示生成内容；可停止生成。无需先选固定问答模板 |
| P0 | 新建与继续聊天 | 左侧列出历史会话，按最近更新排序；点击后恢复消息并在同一会话继续提问 |
| P0 | 会话标题 | 新会话可先显示首条问题的简短标题；用户可在**当前聊天页的标题处**或**历史会话列表**手动重命名。两处显示同一标题，手动标题不会被后续自动覆盖 |
| P0 | 历史保存 | 用户消息在服务端接收后保存；回答完成、失败或中断均保留可辨认状态。重新打开网页后仍能看到历史 |
| P0 | 模型选择 | 默认 DeepSeek Flash；已配置千问密钥时可选择 `qwen3.7-plus`。每条 AI 回复显示所用模型，切换模型不改变旧记录 |
| P0 | 六爻问答 | 能解释已收录概念、比较有出处的不同观点；具体排盘时仅追问必要输入。自由输入为主，可附一个非强制的六次爻值输入区 |
| P0 | 依据与结果 | 默认短答；“展开依据”能看到引用来源、页码/段落和计算口径；回答末尾固定为“最终结果”。缺少证据时如实说明 |
| P0 | 私人访问 | 只有账户持有人可访问聊天与资料；服务器外部访问需 HTTPS 和登录保护 |
| P1 | 管理历史 | 删除或导出单个会话；搜索历史标题和消息内容 |
| P1 | 资料状态页 | 查看 Wiki 已覆盖的来源、待复核资料及错误提取页 |

P0 是首版交付条件；P1 在首版稳定后安排。用户可以在聊天中问一般问题，但服务不得声称尚未进入 Wiki 的资料已被阅读。

## 3. 核心交互规则

1. **会话标题：**当前聊天页顶部和历史列表均显示标题，两个位置都提供重命名入口。任一处改名后，另一处立即同步；刷新后仍保留。重命名只修改会话属性，不修改历史消息。
2. **发送问题：**先显示用户消息和“正在生成”；服务器逐块返回文本。断线、停止或 API 出错时，页面显示清楚的状态，历史中保留已接收内容和失败/中断标记。
3. **继续聊天：**服务从同一会话选取必要的近期上下文、相关 Wiki 页面及已有排盘快照。对同一卦后续追问默认沿用原盘与起卦时点；问题对象或起卦输入发生实质变化时，再要求确认新盘。
4. **具体卦例：**明确记录六次爻值的方向、起卦时间、时区和所用计算口径；排盘由本地程序产生。模型负责解释和归纳，不能改写盘面事实。
5. **引用显示：**来源链接指向包内可查看的 Wiki/清洗文本位置；历史回答保留当时采用的来源 ID、定位和盘面快照，避免资料更新后无法复盘。
6. **回答格式：**先给关键分析，重要分歧才进入默认短答；详细来源按需展开；最后一段为“最终结果”。依据不足时，最终结果明确为“目前资料不足以判断”或同等表述。

## 4. 范围与数据边界

- Wiki 和原件随应用一起打包部署；运行时不访问开发机 `F:` 或 `E:` 盘。每次只向模型发送与当前问题相关的片段和必要图片。
- 聊天记录、会话标题、排盘快照和模型用量存在服务器的持久化目录，升级应用时保留；API Key 只存服务器环境配置。
- Wiki 按目录读取，不使用向量数据库或 embedding。目录读取仍属于运行时引入外部知识，产品文案不得称模型已经“学会全部书”。
- 四个外部仓库的内容在审查后才能进入产品；Skill 中的方法说明与可执行排盘代码分开管理。
- 占断结论属于传统方法下的分析。涉及医疗、财务、法律等现实决策时，页面应提醒用户核查现实证据。

## 5. 已确认的表达

用户确认：**当前正在聊天的会话标题可以重命名，历史会话列表中的标题也可以重命名**。两处操作同一字段；输入消息的文本框不涉及重命名。
