# 六爻 Agent 首版验收清单

版本：2026-10-04。本文供开发方自查和完整产品验收使用。第一阶段网站的最新结论见 [复验记录](phase1_reacceptance_2026-10-02.md)，首次问题见 [首次验收记录](phase1_acceptance_2026-10-02.md)；第二阶段的最新结论见 [提交 39703ef 的二次复验记录](phase2_reacceptance_39703ef_2026-10-04.md)，前两轮问题见 [2026-10-04 复验记录](phase2_reacceptance_2026-10-04.md)和[2026-10-02 验收记录](phase2_acceptance_2026-10-02.md)。完整六爻 Agent 尚未验收。功能依据 [产品需求](product_requirements.md)，接口与数据约束依据 [技术架构](technical_architecture.md)。

第一阶段的网站基础闭环另见 [第一阶段研发任务书](phase1_development_spec.md)；下面的部分条目要等后续 Wiki、排盘和发布阶段完成后才能验收。

## A. 网页与聊天

- [ ] 能登录私人网站，新建会话，输入任意自然语言问题并收到逐步显示的回答。
- [ ] 生成过程中可停止；完成、失败、中断三种状态在页面和历史中都可辨认。
- [ ] 关闭并重开网页或重启服务后，历史会话和消息仍在；点击历史会话可继续对话。
- [ ] 历史列表按最近更新时间排序；**当前聊天页顶部和历史列表都能手动重命名会话标题**，两处立即同步；刷新后保留且不会被自动标题覆盖。
- [ ] 默认模型为 DeepSeek Flash；配置千问后可选用 `qwen3.7-plus`；历史回复显示当时实际调用的模型。
- [ ] 浏览器收到的是流式内容，反向代理未把整段回答缓冲到结束后才显示。历史读取和重命名不需要建立实时连接。

## B. 六爻问答与出处

- [ ] 概念问题能结合已编入 Wiki 的来源回答；没有相应条目时明确说明覆盖不足。
- [ ] 同一概念有不同来源说法时，回答分别标明来源、适用条件和分歧，不混写为单一规则。
- [ ] 具体卦例缺少必要输入时只追问缺项；输入齐全后由本地工具生成盘面，并在回答中标出计算口径。
- [ ] 同一卦后续追问沿用原盘快照；明确的新问题或新输入可建立新盘，不因服务器当前日期变化偷偷重算旧盘。
- [ ] 默认答复简明；可展开来源与计算依据；最后一段为“最终结果”。
- [ ] 展示的每条来源引用均能经来源 ID、页码/章节/段落定位到包内文件；历史回答保留当时的引用快照。
- [ ] 模型文本不能覆盖或修改本地排盘工具给出的确定性字段。至少用固定样例复核卦象、动爻和已实现的关键字段。

## C. 数据、Skill 与安全

- [ ] 原件副本、清洗文本、图片、Wiki、被采用 Skill 的源码快照及许可证都能在发布包中定位；运行不依赖开发机 `F:` 或 `E:` 路径。
- [ ] 只打包已审查并采用的 Skill；记录来源 URL、固定提交版本、依赖和许可。Python 依赖若未进入生产包，生产功能不能暗中调用 Python。
- [ ] 数据库在持久化目录；应用升级后聊天记录仍在，并有可执行的备份和恢复说明。
- [ ] 未登录用户不能读取会话或资料；资料接口不接受任意磁盘路径；错误页面和流事件不暴露 API Key、内部提示词或服务器绝对路径。
- [ ] 发布包和版本库中没有真实 API Key；未配置千问密钥时默认模型仍能工作且界面给出合理说明。

## D. 资料质量门槛

- [ ] 试点资料至少覆盖 TXT、DOCX、旧 DOC、文字 PDF 与扫描 PDF，原件副本有哈希和相对路径清单。
- [ ] 提取失败、乱码、OCR 可疑页在 manifest/质量报告中有状态；这些内容不会被自动提升为已核对的规则。
- [ ] Wiki 规则记录来源、定位、方法标签和整理状态；没有证据时不凭文件名确定作者或流派。
- [ ] 图片链接均指向包内文件；卦象和表格的关键内容若可结构化表达，保留对应文本。

## 验收方法与记录

开发方提交可启动发布包、部署说明、试点资料清单、固定问答样例及排盘样例。验收时按上述项目逐项记录“通过 / 未通过 / 不适用”和证据链接。软件验收关注来源可追踪、盘面一致性、聊天持久化与实际交互；不以占断对现实事件的命中率作为软件正确性的证明。
