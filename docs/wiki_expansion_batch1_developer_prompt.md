# 交给研发 AI 的本地 Wiki 第一批扩充提示词

请现在启动[本地 Wiki 扩充第一批任务书](wiki_expansion_batch1_spec.md)，与[第五阶段 Docker 发布](phase5_development_spec.md)并行，使用独立分支/工作区避免互相覆盖。先核对 `docs/source_inventory.csv`、`docs/pilot_source_assessment.md`、`corpus/manifest.jsonl`、`wiki/index.md`、`wiki/catalog.json` 和现有资料 CLI 的真实接口，再交一页批次设计，之后才处理来源。

本批候选为 `F:\道教\六爻` 下的 `五行所属行业/六爻取用神诀窍.txt`、`五行所属行业/六神临六亲取象.txt`、`六爻断卦技法.txt`、`六爻特训班讲义 曲炜1 .txt`。F 盘只读，原件复制进项目并重新核对哈希。四份先做全文可定位提取与 Markdown 清洗；长讲义可先把明确标注的已核对章节编入 Wiki，其余范围必须如实标记。近名版本先比较，不能凭文件名合并；质量差或重复时按任务书记录替换理由。

先建来源页，再把有原件定位的主张纳入概念/对照页，保留作者/版本自述与方法分歧。同步更新 `wiki/index.md`、维护日志和目录，确保 Agent 对相关问题能选到新页，并保留阶段 2 的六份样本与第四阶段历史快照。

修正用户已经遇到的表达问题：实现从 manifest 和 Wiki 目录生成的收录范围回答，明确区分“已导入原件”“已提取/清洗”“已编入可引用 Wiki”“本轮实际用到的来源”。不要让模型根据这次只收到两个 `Sx` 就声称库里只录入两份。给出“录入了哪些资料”“是否收录某文件”“本轮引用哪几份”的实测输出。

交付 `docs/wiki_expansion_batch1_delivery.md`、可复制的重跑/验收命令、包内相对路径与哈希清单、实际覆盖和质量边界、未完成项及 Git 提交 SHA。研发自测不等于独立验收。新增资料通过独立验收并与第五阶段冻结版本对齐后，才能进入正式 Docker 发布包；不要把未核对文本自动提升为六爻规则或现实预测事实。
