# 给开发 AI 的交接说明

版本：2026-10-01。用户指定其他 AI 负责编码；本项目的需求、架构和验收文档由产品/架构方维护。开始前按顺序阅读 [产品需求](product_requirements.md)、[技术架构](technical_architecture.md)、[研发计划](development_plan.md) 和 [验收清单](acceptance_checklist.md)。早期 Python/FastAPI 草案仅作资料处理历史参考。

用户可将[第一阶段开发 AI 提示词](phase1_developer_prompt.md)直接发送给研发 AI。详细接口与阶段验收场景以[第一阶段研发任务书](phase1_development_spec.md)为准。

## 第一项研发任务：网站基础闭环

按[第一阶段研发任务书](phase1_development_spec.md)实现单用户登录、自由聊天页面、左侧历史会话列表、**当前聊天页与历史列表均可重命名同一会话标题**、DeepSeek Flash 流式回复、停止生成，以及 SQLite 持久化。网页和 API 使用 Node.js/TypeScript + Next.js；AI 回复用 `POST` 返回 SSE 格式流，浏览器以 `fetch` 读取。聊天内容、标题及生成状态须在刷新和服务重启后保留。

本阶段可用占位 Wiki 页面展示后续出处区域，但不得声称已接入完整六爻资料。尚不需要安装 PostgreSQL，也不需要把四个外部仓库安装到全局 Skill 目录。应用中的 API Key 只由服务器环境提供。

## 阶段提交物

开发方提交可运行代码、锁定依赖文件、启动与配置说明、数据迁移及备份说明，并列出已完成/未完成的验收项。说明实际采用的模型接口、流事件格式、数据库文件路径、会话重命名规则和中断状态处理。若技术实现偏离架构，需要记录原因、代价及迁移影响，交由产品/架构方复核。

第一阶段通过后，再按研发计划推进资料试点、Wiki、Skill 审查和排盘模块。任何资料来源或第三方代码采用前都须留下出处、版本、许可与质量记录。
